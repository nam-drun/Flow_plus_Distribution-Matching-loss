# Why care?
Current SOTA in image generation is MDP + RLHF. For example, see [Qwen Image 2.0 technical reports](https://arxiv.org/pdf/2606.27608v1)). Recently, people have figured out that you can post-train flow models with various distribution matching losses such as:
- Fréchet distance, see [FD loss paper](https://arxiv.org/abs/2604.28190).
- Adversarial GAN on Fréchet distance, see [AdvFD loss paper](https://arxiv.org/abs/2608.11205).
- KL, see [TDM paper](https://arxiv.org/abs/2503.06674) and [Mgflow paper](https://arxiv.org/abs/2609.35763).

We think that all these papers including current SOTA share the same common in leveraging discretisation error produced by pretrained model to recover clean image $X_1$. For starter, if you want to use RLHF during post-training, you redesign transport (multi-step denoising process) as MDP. This is because you can't use RLHF directly on Flow Matching as shown by [Flow-GRPO paper](https://arxiv.org/abs/2505.05470). This, of course, comes at the cost of making the "decision" (or "transition" part if you go by diffusion language) very degenerate. E.g., The state transition is literally just modelling the sampling of the action $a \sim p(a|x)$ as a dirac delta on the chosen $a$ (i.e. you get the sampling action without leaving "density" language: you use the fact that $\mathbb{E}_{X \sim p(x)}[\delta_X] = p(x)$, i.e. in some sense this passes through the density like an identity). Now, to properly connect MDP to Flow Matching, you need to go via Hamilton-Bellman-Jacobi <-> Hamilton-Jacobi <-> Wasserstein, where Flow Matching is basically Wasserstein-2 optimal transport. Even so, this is a quasi unclear connection. Now, this connection matters because at the moment, Flow Matching is soundly much more compute efficient than MDP (transport is just a very neat way to sampling). Therefore:
- If MDP can inherit the "compute efficiency" aspect of Flow Matching via RLHF. Then that's it, everyone will migrate to MDP + RLHF.
- But if not. Then Flow Matching + distribution matching loss provides a cheap alternative for anyone who doesn't have enough compute to post-train MDP + RLHF.

***If the intuition from IMDE is found in MDP + RLHF, like we have discovered its presence in Flow Matching + distribution matching, then it will provide more avenue to explore on how to make MDP + RLHF inherits the "compute efficiency" aspect of Flow Matching.***

# Flow Matching recap
If you try to sample any distribution in practice, you will see a point cloud. Suppose you transport all samples of this distribution to some other positions in space after $T$ time, then you will get another distribution $P_t$ (unless somehow $X_0 = X_T$). In physics, you learn about *displacement = velocity x time*, i.e., $X_{t_{k+1}} = X_{t_k} + \Delta t v(t_k, X_{t_k}$. Same idea applies for here. During sampling, given $X_0 \sim \mathcal{N}(0, I_d)$, you "transport" that sample to $X_1$ using *next position = current position + velocity x time*, which is literally the case if you use Euler integration solver, but still holds true for more accurate solvers like Heun and Dormand-Prince 5(4). Now, set $T = 1$, $P_0 = \mathcal{N}(0, I_d)$ and $P_1 = $ *data distribution*, then you have discovered flow matching

The next step in flow matching is find out how to train the neural network on velocity. So where is velocity coming from during training? Again in physics, you learn that velocity = derivative of current position $X_t$. Same idea applies here. First, you sample a random pair of "start point, end point": $`\left\{X_0,X_1\right\}`$ with $X_0 \sim \mathcal{N}(0, I_d)$ being pure noise and end point $X_1$ being accessible image during training. Then you compute $X_t$ using noise schedule $\alpha_t$ and $\beta_t$. E.g., if you use VP schedule from DDPM diffusion, then $X_t = \sqrt{1 - t^2}X_0 + tX_1$; if you use linear schedule from [JiT paper](https://arxiv.org/abs/2511.13720v1) then $X_t = (1-t)X_0 + tX_1$. From $X_t$, you take its derivative $\dot{X}_t$ to acquire velocity $v(t, X_t)$. Now, if multiple trajectories intersect at some random point $X_t = x$, you can't really feed multiple "velocities" to the neural network. So the compromise is to take their averages $v(t, x) = \mathbb{E}[\dot{X}_t \mid X_t = x]$. Note, this is also why people use the term "velocity field" $v(t, x)$ instead of "velocity" $v(t, X_t)$ (or $\dot{X}_t$) in flow matching. But, if the ambient space $\mathbb{R}^d$ has high number of dimensions, which is always true in image generation), then $\mathbb{E}[\dot{X}_t \mid X_t = x] \approx \dot{X}_t$. So it's fine to treat "velocity field" as if it is "velocity". In the picture below, we show how Flow Matching works using Base Continuous $X_t$ and Base Euler, where Base Euler $\hat{X}_t$ is what $X_t$ would look like if we reconstruct it use Euler with 4 sampling steps. Lastly, for modern diffusion, you add-on random noise during sampling, whether this is practically useful or not is questionable. Side note, modern diffusion are distinguished from classical diffusion by using score or denoiser term to derive velocity field to treat the entirety of sampling process as transport (recall the *next position = current position + velocity x time*). Whereas if you look at diffusion in the early days, either they use MCMC (Langevin dynamics) during sampling, see page 4 in ([Yang Song-Kingma 2021 paper](https://arxiv.org/abs/2101.03288)); or they use mean and covariance to treat sampling as a sequence of Gaussian transitions.


# How to leverage discretisation error, instead of fighting it
Given some pretrained velocity field $v_{Base}(t, x)$, it is not a surprise that during post-training, distribution matching loss perturbs $v_{Base}(t, x)$. This means that for the same start point $X_0$, $v_{perturbed}(t, x)$ will transport $X_0$ along some different trajectory (Perturbed Continuous) to arrive a different endpoint. Assume that $v_{Base}(t, x)$ and $v_{perturbed}(t, x)$ are perfectly learned, respectively. 
> You can learn a perturbed velocity field that belongs to some ***specific*** Perturbed Continuous trajectory, such that its Perturbed Euler can recover $X_1$ exactly (see the left panel in the picture below).

In other words, you intentionally learn different velocity field that Flow Matching considers "wrong" (i.e., not arriving $X_1$ in continuous-sense), but still arriving $X_1$ during sampling by leveraging discretisation error, which is the ideal scenario in Flow Matching (see the left panel in the picture below). How is this possible? It's because discretisation error $e^{disc}$ is not a random arbitrary construct, it is $`X_t - \hat{X}_t`$ after all. Now, there are 2 ways to think about $X_t$: You can think of $X_t$ like how Flow Matching does it; or you can think of $X_t$ as Euler (or any solver really) with infinite sampling steps $`X_t = X_0 + \int_0^t v(s, X_s) ds \approx X_0 + \delta t \sum_{k=0}^{N-1} v(t, X_{t_k})`$, where $`\delta t = \frac1N`$ with $`N \to \infty`$. By comparison, for 4 sampling steps, $`\hat{X}_t = X_0 + \frac14 \sum_{k=0}^{4-1} v(t, X_{t_k})`$. Plug these into $X_t - \hat{X}_t$, we get $`\delta t \sum_{k=0}^{N-1} v(t, X_{t_k}) - \frac14 \sum_{k=0}^{4-1} v(t, X_{t_k})`$. Now, if we want the left panel, then $`\frac14 \sum_{k=0}^{4-1} v(t, X_{t_k})`$ has to be $X_1$. Meaning $`\delta t \sum_{k=0}^{N-1} v(t, X_{t_k})`$ has to be $X_1 + e^{disc}$, which is what Perturbed Continuous is. 

However, not all Perturbed Continuous can recover $X_1$. As you can see in the right panel, some other Perturbed Continuous is unable to their corresponding Perturbed Euler to arrive $X_1$. This leads to an important question. How can we train the neural network to know which is which? This naturally leads us to [IMDE paper](https://arxiv.org/abs/2206.07335), which we discuss in [left-panel-to-IMDE.md](https://github.com/nam-drun/Flow_plus_Distribution-Matching-loss/blob/main/left-panel-to-IMDE.md). Enjoy reading.
