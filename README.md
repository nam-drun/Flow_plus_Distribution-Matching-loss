# Why care?
Current SOTA in image generation is MDP + RLHF. For example, see [Qwen Image 2.0 technical reports](https://arxiv.org/pdf/2606.27608v1)). Recently, people have figured out that you can post-train flow models with various distribution matching losses such as:
- Fréchet distance, see [FD loss paper](https://arxiv.org/abs/2604.28190).
- Adversarial GAN on Fréchet distance, see [AdvFD loss paper](https://arxiv.org/abs/2608.11205).
- KL, see [TDM paper](https://arxiv.org/abs/2503.06674) and [Mgflow paper](https://arxiv.org/abs/2609.35763).

We argue that all these papers including the current SOTA share the same common in utilising post-training to counteract the discretisation error produced by pretrained model (be it Flow or MDP). The last part is interesting because MDP's connection to Flow Matching isn't clear. From [Flow-GRPO paper](https://arxiv.org/abs/2505.05470), we learn that in order to use RLHF (since you can't just make RLHF working with Flow Matching directly), you first need to formulate the flow process (or multi-step denoising process) as Markov Decision Process (MDP). This comes at the cost of making the "decision" or "transition" part very degenerate. E.g., The state transition is literally just modelling the sampling of the action $a \sim p(a|x)$ as a dirac delta on the chosen $a$ (i.e. you get the sampling action without leaving "density" language: you use the fact that $\mathbb{E}_{X \sim p(x)}[\delta_X] = p(x)$, i.e. in some sense this passes through the density like an identity). If you want to formally connect MDP to Flow Matching, you need to go via Hamilton-Bellman-Jacobi <-> Hamilton-Jacobi <-> Wasserstein, where Flow Matching is built from Wasserstein space (see section 3.4 in [Stochastic Interpolant paper](https://arxiv.org/abs/2303.08797)). In short, there's some chance that MDP is connected to Flow Matching, but it's not clear. What is clear is that MDP is nowhere near as compute efficient as Flow Matching. 

Because it's not a clear yes or no on whether MDP is actually connected to Flow Matching; and because Flow + post train with distribution matching loss actually works (including KL); and because KL is an important term in GRPO loss, see equation (3) in [Flow-GRPO paper](https://arxiv.org/abs/2505.05470). Altogether, these open up 2 interesting scenarios. 
1. Maybe MDP turns out to be the "distant prodigy heir" of Flow Matching, where it takes KL term to "unlock" the potential of MDP during post-training with RLHF. This means that everyone should migrate to MDP + RLHF for image generation.
2. Or maybe MDP is not the distant prodigy heir. Meaning practitioners have 2 choices: if they have lots of compute to post-train, use MDP + RLHF; if not, use Flow + distribution matching loss. This is because Flow Matching is already much more compute efficient than MDP, and post-training with distribution matching loss only makes Flow Matching even more compute efficient.
   
In this work, we investigate to see which scenario is more likely true.

# How to leverage discretisation error, instead of fighting it
First, let's recap modern diffusion/flow matching. If you sample any distribution, you will get a point cloud. The idea behind Optimal Transport is that if you literally move (i.e., transport) all samples ("points") from their starting points $X_0$ to some end points $X_1$, then you will get a different distribution $P_1$ (unless somehow $X_0 = X_1$). Now suppose $P_1$ is identical to data distribution $P^*$ and $P_0 = \mathcal{N}(0, I_d)$, then you have discovered flow matching. The next step to figure out how to train the neural network. In physics, you learn about *displacement = velocity x time* (i.e., $X_{t_{k+1}} = X_{t_k} + \Delta t v(t_k, X_{t_k}$). Same idea applies for "transport". During sampling, given $X_0 \sim \mathcal{N}(0, I_d)$, you "transport" that sample to $X_1$ using *current position = previous position + velocity x time*, which is literally the case if you use Euler integration solver, but still holds somewhat true for more accurate solvers like Heun and Dormand-Prince 5(4). During training, you train neural network to learn ground truth velocity field $v(t, x)$ via mean-squared error (there's a reason why it's called "velocity field" rather than just "velocity"). So where is $v(t, x)$ coming from? Again in physics, you learn that velocity = derivative of current position $X_t$. Same idea applies here. First, you sample a random pair of "start point, end point": $`\left\{X_0,X_1\right\}`$ with $X_0 \sim \mathcal{N}(0, I_d)$ being pure noise and end point $X_1$ being accessible image during training. Then you compute $X_t$ using noise schedule $\alpha_t$ and $\beta_t$. E.g., if you use VP schedule from DDPM diffusion, then $X_t = \sqrt{1 - t^2}X_0 + tX_1$; if you use linear schedule from [JiT paper](https://arxiv.org/abs/2511.13720v1) then $X_t = (1-t)X_0 + tX_1$. From $X_t$, you take its derivative $\dot{X}_t$ to acquire velocity $v(t, X_t)$. Now, if multiple trajectories intersect at some random point $X_t = x$, you can't really feed multiple "velocities" to the neural network. So the compromise is to take their averages $v(t, x) = \mathbb{E}[\dot{X}_t \mid X_t = x]$, hence why we use the term "velocity field" $v(t, x)$ instead of "velocity" $v(t, X_t)$ (or $\dot{X}_t$) in modern diffusion/flow matching. But, if the ambient space $\mathbb{R}^d$ has high number of dimensions (which is always true in image generation), then $\mathbb{E}[\dot{X}_t \mid X_t = x] \approx \dot{X}_t$. So it's fine to treat "velocity field" as if it is "velocity". For diffusion, you add-on random noise during sampling, whether this is practically useful or not is questionable. Second, given some pretrained velocity field $v_{Base}(t, x)$, it is not a surprise that distribution matching loss perturbs $v_{Base}(t, x)$. This means that for the same start point $X_0$, $v_{perturbed}(t, x)$ will transport $X_0$ along some different trajectory (Perturbed Continuous) to arrive a different endpoint. Assume that $v_{Base}(t, x)$ and $v_{perturbed}(t, x)$ are perfectly learned, respectively. 
> You can learn a perturbed velocity field that belongs to some ***specific*** Perturbed Continuous trajectory, such that its Perturbed Euler can recover $X_1$ exactly (see the left panel in the picture below).

In other words, you can ignore the intuition behind Flow Matching by intentionally learn different velocity field, but still arriving $X_1$ during sampling by leveraging discretisation error, which is the ideal scenario in Flow Matching (see the left panel in the picture below). But how is this possible? It's possible because discretisation error $e^{disc}$ is not a random arbitrary construct, it is $`\left\|X_t - \hat{X}_t\right\|`$ after all. Now, there are 2 ways to think about $X_t$: You can think of $X_t$ like how Flow Matching does it; or you can think of $X_t$ as Euler with infinite sampling steps. In math term, this is $`X_t = X_0 + \int_0^t v(s, X_s) ds \approx X_0 + \delta t \sum_{k=0}^{N-1} v(t, X_{t_k})`$, where $`\delta t = \frac1N`$ with $`N \to \infty`$. By comparison, for 4 sampling steps, $`\hat{X}_t = X_0 + \frac14 \sum_{k=0}^{4-1} v(t, X_{t_k})`$. Plug these into $`\left\|X_t - \hat{X}_t\right\|`$, we get $`\left\|\delta t \sum_{k=0}^{N-1} v(t, X_{t_k}) - \frac14 \sum_{k=0}^{4-1} v(t, X_{t_k})\right\|`$. Now if we want, $`\hat{X}_t := X_1`$, then $v(t, X_{t_k})$ has to be some specific velocity field. Meaning $X_t$ has to be some specific trajectory, which is our established idea above. Now, there is a limitation to this idea, if you learn some perturbed velocity field that belongs to a wrong Perturbed Continuous trajectory, then instead of leveraging discretisation error to recover $X_1$, your model will succumb to discretisation error even worse (see the right panel in the picture below).

- Any distribution matching loss would learn some ***specific*** Perturbed Continuous trajectory that achieves the left panel instead of the right panel in the picture above. E.g., why would Fréchet distance, a loss function that matches mean and covariance, would encourage the neural network learn this ***specific*** trajectory?
- Learning this ***specific*** trajectory would lead to a generated distribution that is closely matching $P^*$ than $P_1$. Remember, we have just ignored Flow Matching by intentionally learn a different velocity field. So why would this work?
