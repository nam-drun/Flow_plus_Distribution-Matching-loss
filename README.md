# Why care?
Current SOTA in image generation is MDP + RLHF. For example, see [Qwen Image 2.0 technical reports](https://arxiv.org/pdf/2606.27608v1)). Recently, people have figured out that you can post-train flow models with various distribution matching losses such as:
- Fréchet distance, see [FD loss paper](https://arxiv.org/abs/2604.28190).
- Adversarial GAN on Fréchet distance, see [AdvFD loss paper](https://arxiv.org/abs/2608.11205).
- KL, see [TDM paper](https://arxiv.org/abs/2503.06674) and [Mgflow paper](https://arxiv.org/abs/2609.35763).

We think that all these papers including current SOTA share the same common in leveraging discretisation error produced by pretrained model to recover clean image $X_1$. For starter, if you want to post-train with  Reinforcement Learning with Human Feedback (RLHF) like how [Flow-GRPO paper](https://arxiv.org/abs/2505.05470) or Qwen Image 2.0 do it, you will need to change switch formulation from transport (multi-step denoising process) to Markov Decision Process (MDP). This is because you can't use RLHF directly on Flow Matching as shown by [DDPO paper](https://arxiv.org/abs/2305.13301) in their introduction. This comes at the cost of making the "decision" (or "transition" part if you go by diffusion language) very degenerate. E.g., The state transition is literally just modelling the sampling of the action $a \sim p(a|x)$ as a dirac delta on the chosen $a$ (i.e. you get the sampling action without leaving "density" language: you use the fact that $\mathbb{E}_{X \sim p(x)}[\delta_X] = p(x)$, i.e. in some sense this passes through the density like an identity). Now, to properly connect MDP to Flow Matching, you need to go via Hamilton-Bellman-Jacobi <-> Hamilton-Jacobi <-> Wasserstein, where Flow Matching is Wasserstein-2 optimal transport. Even so, this is a quasi unclear connection. Now, this connection matters because at the moment, Flow Matching is soundly much more compute efficient than MDP (transport is just a very neat way to sampling). Therefore:
- If MDP can inherit the "compute efficiency" aspect of Flow Matching via RLHF. Then everyone will migrate to MDP + RLHF.
- But if not. Then Flow Matching + distribution matching loss provides a cheap alternative for anyone who doesn't have enough compute for MDP + RLHF.

***If the intuition from IMDE is found in MDP + RLHF, like how we have discovered its presence in Flow Matching + distribution matching, then it will provide more avenue to explore on how to make MDP + RLHF inherits the "compute efficiency" aspect of Flow Matching.*** The 3 toy experiment results show that Flow Matching + KL works much better compared to Flow Matching + FD and Flow Matching + AdvFD.

# Flow Matching recap
If you try to sample any distribution in practice, you will see a point cloud. Suppose you transport all samples of this distribution to some other positions in space after $T$ time, then you will get another distribution $P_t$ (unless somehow $X_0 = X_T$). In physics, you learn about *displacement = velocity x time*, i.e., $X_{t_{k+1}} = X_{t_k} + \Delta t v(t_k, X_{t_k})$. Same idea applies for here. During sampling, given $X_0 \sim \mathcal{N}(0, I_d)$, you "transport" that sample to $X_1$ using *next position = current position + velocity x time*, which is literally the case if you use Euler integration solver, but still holds true for more accurate solvers like Heun and Dormand-Prince 5(4). Now, set $T = 1$, $P_0 = \mathcal{N}(0, I_d)$ and $P_1 = $ *data distribution*, then you have discovered flow matching

The next step in flow matching is find out how to train the neural network on velocity. So where is velocity coming from during training? Again in physics, you learn that velocity = derivative of current position $X_t$. Same idea applies here. First, you sample a random pair of "start point, end point": $`\left\{X_0,X_1\right\}`$ with $X_0 \sim \mathcal{N}(0, I_d)$ being pure noise and end point $X_1$ being accessible image during training. Then you compute $X_t$ using noise schedule $\alpha_t$ and $\beta_t$. E.g., if you use VP schedule from DDPM diffusion, then $X_t = \sqrt{1 - t^2}X_0 + tX_1$; if you use linear schedule from [JiT paper](https://arxiv.org/abs/2511.13720v1) then $X_t = (1-t)X_0 + tX_1$. From $X_t$, you take its derivative $\dot{X}_t$ to acquire velocity $v(t, X_t)$. Now, if multiple trajectories intersect at some random point $X_t = x$, you can't really feed multiple "velocities" to the neural network. So the compromise is to take their averages $v(t, x) = \mathbb{E}[\dot{X}_t \mid X_t = x]$. Note, this is also why people use the term "velocity field" $v(t, x)$ instead of "velocity" $v(t, X_t)$ (or $\dot{X}_t$) in flow matching. But, if the ambient space $\mathbb{R}^d$ has high number of dimensions, which is always true in image generation), then $\mathbb{E}[\dot{X}_t \mid X_t = x] \approx \dot{X}_t$. So it's fine to treat "velocity field" as if it is "velocity". In the picture below, we show how Flow Matching works using Base Continuous $X_t$ and Base Euler, where Base Euler $\hat{X}_t$ is what $X_t$ would look like if we reconstruct it use Euler with 4 sampling steps. Lastly, for modern diffusion, you add-on random noise during sampling, whether this is practically useful or not is questionable. Side note, modern diffusion are distinguished from classical diffusion by using score or denoiser term to derive velocity field to treat the entirety of sampling process as transport (recall the *next position = current position + velocity x time*). Whereas if you look at diffusion in the early days, either they use MCMC (Langevin dynamics) during sampling, see page 4 in ([Yang Song-Kingma 2021 paper](https://arxiv.org/abs/2101.03288)); or they use mean and covariance to treat sampling as a sequence of Gaussian transitions.


# How to leverage discretisation error, instead of fighting it
Given some pretrained velocity field $v_{Base}(t, x)$, it is not a surprise that during post-training, distribution matching loss perturbs $v_{Base}(t, x)$. This means that for the same start point $X_0$, $v_{perturbed}(t, x)$ will transport $X_0$ along some different trajectory (Perturbed Continuous) to arrive a different endpoint. Assume that $v_{Base}(t, x)$ and $v_{perturbed}(t, x)$ are perfectly learned, respectively. 
> You can learn a perturbed velocity field that belongs to some ***specific*** Perturbed Continuous trajectory, such that its Perturbed Euler can recover $X_1$ exactly (see the left panel in the picture below).

![the picture below](https://github.com/nam-drun/Flow_plus_Distribution-Matching-loss/blob/main/discretisation-error.png)

In other words, you intentionally learn a different velocity field that Flow Matching considers "wrong" (i.e., not arriving $X_1$ with Base Continuous), but still arriving $X_1$ with Perturbed Euler during sampling by leveraging discretisation error (see the left panel in the picture below). This brings us 2 questions: 
- How to find Perturbed Continuous?
- And how can distribution matching loss during training find Perturbed Continuous? 

For the first question, define discretisation error of Base Continuous as $e_B^{disc} = X_1 - \hat{X}_1$. Now, because $`\left\{X_0,X_1\right\}`$ is drawn randomly. Having access to $X_1$ is easy if you have pretrained the Flow Matching/Diffusion model from scratch. But if you have the access to the pretrained checkpoint, then you will need to continue pretraining the model just to have access to $X_1$. So long as $\mathbb{E}[\dot{X}_t \mid X_t = x] \approx \dot{X}_t$ (which is true for high $\mathbb{R}^d$), then you can trust that the end point produced from the same $X_0$ during sampling is the discretised endpoint of $X_1$. In other words, you can trust that $\hat{X}_1$ actually belongs to ***that particular*** $X_1$ not some other end point. Now, as the left panel visually hints at, the end point of Perturbed Continuous needs be opposite of the end point of Base Euler, with both sides centered at $X_1$. This makes sense, if you want the end point of Perturbed Euler to be $X_1$ and you want to leverage $e^{disc}$ to get there, then the end point of Perturbed Continuous need to be $X_1 + e_B^{disc}$. By comparison, the end point of Base Euler is produced by $X_1 - e_B^{disc}$ so the twos are opposite of each other. 

Now of course, doing this at scale is not scalable. This is why the 2nd question matters a lot. How does FD, AdvFD, KL figure this out and manage to do this at scale. To answer this question, first we'll connect our intuition from the left panel to [IMDE paper](https://arxiv.org/abs/2206.07335) in [left-panel-to-IMDE.md](https://github.com/nam-drun/Flow_plus_Distribution-Matching-loss/blob/main/left-panel-to-IMDE.md); then we'll use IMDE paper to match with each toy result pattern from each distribution matching loss.
