# Why care?
We have figured out that most distribution matching losses, such as Frechet Distance, GAN Adversarial, KL, could counteract for discretisation error. This might help us understand how RLHF helps in MDP in image generation (see Qwen-Image 2.0). Until someone proves that RLHF cannot counteract for discretisation error, this remains an interesting possibility to figure out? Then, we also have figured out that among the three distribution matching losses, only KL manages to continue working even when we use more accurate solvers such as Heun or Dormand-Prince 5(4). So it's not a clear whether with the right setup, Flow + KL can beat the current SOTA in image generation, which is MDP + RLHF (see Qwen Image 2.0 technical reports).

# How can discretisation error be counteracted?
First, we want to capture the overall picture of modern diffusion/flow matching. If you sample any distribution, you will get a point cloud. The idea behind Optimal Transport is that if you literally move (i.e., transport) all samples ("points") from their initial position $X_0$ to some different destinations $X_1$, then you will get a different distribution $P_1$. Now suppose $P^* = P_1$ and $P_0 = \mathcal{N}(0, I_d)$, then you just deduce the basic setup for modern diffusion/flow matching. The next step to figure out how to quantify "transport" in a way such that neural network can learn and generalise it. In high school physics, you have learnt about *displacement = velocity x time*. Same idea applies for "transport". During sampling, you have access to $X_0$, so you "transport" a sample to $X_1$ using *next position = current position + velocity x time* (this is literally the case if you use Euler integration solver, but still holds somewhat true for more accurate solvers like Heun and Dormand-Prince 5(4)). Next, you train neural network to learn ground truth velocity field $v(t, X_t)$ via mean-squared error (there's a reason why it is called "velocity field" rather than just "velocity"). So where is $v(t, X_t)$ coming from? In high school physics, velocity = derivative of current position $X_t$. Same idea applies for modern diffusion/flow matching. First, you sample a random pair of endpoints $`\left\{X_0, X_1\right\}`$ with $X_0$ being pure noise and $X_1$ accessible image during training. Then you compute $X_t$ using noise schedule $\alpha_t$ and $\beta_t$. E.g., if you use VP schedule from DDPM diffusion, then $X_t = \sqrt{1 - t^2}X_0 + tX_1$; if you use linear schedule from [JiT paper](https://arxiv.org/abs/2511.13720v1) then $X_t = (1-t)X_0 + tX_1$. From $X_t$, you take its derivative $\dot{X}_t$ to acquire velocity. Now, if multiple trajectories intersect at $X_t$, you can't really feed multiple "velocities" to neural network. So the compromise is to take their averages, hence the formula $v(t, X_t) = \mathbb{E}[\dot{X}_t \mid X_t = x]$. This is also why we use the term "velocity field" instead of just "velocity" in modern diffusion/flow matching. But, if the ambient space $\mathbb{R}^d$ has high number of dimensions (always true in image generation), then $\mathbb{E}[\dot{X}_t \mid X_t = x] \approx \dot{X}_t$, it's fine to treat "velocity field" like "velocity". For diffusion, you add-on random noise during sampling, whether this is practically useful or not is questionable.

Second, we want to establish an idea that for the same solver and the same amount of sampling steps, direction of discretisation error is consistent in term of direction and displacement - see the picture below. In the picture below, look at direction and displacement between Base Continuous vs Base Euler; and look at direction and displacement between Perturbed Continuous vs Perturbed Euler, you will see that their direction and displacement are the same. This is not a coincidence and we'll analyse this using Alekseev-Grobner formula in a separated post. For the moment, what's important is that this idea leads to another crucial idea: a neural network can learn some perturbed velocity field from Perturbed Continuous trajectory such that the discretisation error itself can be utilised to reproduce the ideal $X_1$ (see left panel in picture below). This is essentially the intuition behind theorem 3.2 in [IMDE paper](https://arxiv.org/abs/2206.07335).

# How could distribution matching loss counteract discretisation error?
Because discretisation error is consistent in both direction and displacement. This means that for every Base Continuous, there is only 1 correct Perturbed Continuous that could recover ideal $X_1$ among infinite Perturbed Continuous trajectories that fail to do so. Now looking at Frechet Distance, Adversarial GAN, or KL, there's nothing in those distribution matching losses that explicit train the network to do this.
